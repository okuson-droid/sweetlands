# decisions.md 追補 §10：準備の選択の改訂とヴァリアント2種（2026-10-11）

準拠：`SweetLands_rules_v1.1.md`（rules v1.1）。ルールの決定はそちらに書き、ここには実装上の判断を記録する。

## 10.1 ユーザー確認で決まった点

- 準備のドラフトの順番：プレイヤーをスタートプレイヤーを1として時計回りに番号付けし、N…1, 1…N, N…1。2人・3人も同じ形（21 12 21、321 123 321）。
- 2つのヴァリアント（キャラクターの自由選択、準備のドラフト）は別々に採用できる。ドラフトでも、自由選択を採用していなければ、選ばれたキャラクターの裏面は選べない。
- ドラフトの「ラウンド支援ボード」は、第1ラウンドに使うラウンド支援駒の初期スペースを選ぶこと。
- 地図ボードの A面は複数人が選べる。ただし A面を選ぶときも、どのボード（裏がどのB面か）を使うかを選び、そのボードの B面は以降選べない。これはドラフトに限らず、通常の準備でも同じ（実物の準備手順そのもの）。

## 10.2 実装

- `GameConfig.variants` に `freeChar`（§10.4）と `setupDraft`（§10.5）を足した。以前の記録との互換のため省略可で、未定義は不採用として扱う。
- `PlayerState.mapBoard`：受け取った地図ボード（B面の仮番号 B1〜B5）。`mapId` は使う面（'A' または 'B1'〜'B5'）。
- 地図ボードの合法手 ID：B面は `map:B3`、A面は `map:A@B3`（B3 のボードの A面）。
- 旧形式の記録（ボード指定のない `map:A`）は、`applyMove` で「受け取られていない最初のボードの A面」に読み替える。ローカルに保存された途中のゲームを再生できるようにするため。
- ドラフトは新しい選択待ち `setupPick`。選択肢は、その人がまだピックしていない種類の選択肢を合わせたもの（`char:…`・`map:…`・`col:…`）。どの種類をピック済みかは `character`・`mapId`・`supportSpace` が埋まっているかで判定し、新しい状態は持たない。
- 画面：`targetOf` は `setupPick` の選択肢を種類ごとに通常の準備と同じ対象へ対応させる。ドラフトの小窓（`Dialogs.tsx` の `DraftWindow`）は、ピックの順番・各プレイヤーのピック済みの内容・3種類のタブを出す。ラウンド支援駒のタブではラウンド支援ボードをそのまま描き、スペースのクリックか支援駒のドラッグで選ぶ。
- ロビー：ヴァリアントの欄に2つのチェックを足した。自動対戦の `v=1` は5つのヴァリアントをすべて採用する。

## 10.3 テスト
