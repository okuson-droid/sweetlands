# decisions.md 追補 §13：機能の追加（2026-10-12）

準拠：`SweetLands_rules.md`（v1.0）と `SweetLands_rules_v1.1.md`（v1.1）。ルールとルールエンジンの判定は変えていない。選択肢 ID と乱数の消費も変えていない。

## 13.1 リプレイと最終盤面

- オンライン対戦のリザルトの「リプレイを見る」は何もしなかった（`Online.tsx` で空の処理を渡していた）。ローカル対戦と同じ `ReplayScreen` を開くようにした。
- リザルトに「最終盤面を見る」を足した。リプレイ画面を最後の手の位置で開く。「リプレイを見る」は最初（0手目）から開く。
- `ReplayScreen` に開く位置（`at: 'start' | 'end'`）を足した。

## 13.2 対局中の集計

- 個人ボードのキャラクター名の行の下に、次の集計を出す（`TallyLine`）。
  - 置いた地形タイルの枚数：麦畑・森林・鉱山・海ごと。特殊地形タイルは置いたときだけ出す。
  - 置いた道駒の本数。
  - プレイしたカードの枚数：産業タグ（農業・林業・鉱業）ごと。オートメーション化したカードも含める。
- 産業タグは、カードの産業そのもので数える。オールマイティのカードは農業・林業・鉱業に重ねず、別の数として出す（ある場合のみ）。産業タグのないカードも、ある場合のみ別に出す。時計塔駒の条件の判定（`playedCount`）はオールマイティを各産業に含めるが、集計の表示は重複を避けるため分けた。
- 集計は `queries.ts` の `tally` で計算する（純粋関数。`tests/rules.test.ts` で検査する）。

## 13.3 手番の最初に戻る

- 1手の取り消しとは別に、帯に「手番の最初に戻る」を足した。取り消せる手が2手以上あるときだけ出す。
- 戻る先は、取り消せる範囲の先頭（チェックポイント）である。手番が変わるとチェックポイントになるため、通常は手番の最初に戻る。手番の途中で山札を引くなど新しい情報が出た場合は、その時点より前には戻らない（1手の取り消しと同じ制約）。
- `GameSession.undoAll` をローカル（`useGame`）とオンライン（`useOnlineGame`）の両方に足した。オンラインでは手の列をチェックポイントまで縮めて送る。
- e2e の自動操作は、このボタンを1手の取り消しと同じく押さない。

## 13.4 ログ

- 取り消した手のログは、以前は取り消し線を引いて残していた。手の列が縮んだら、それより後の手で出た行を消すようにした（1手の取り消しでも、手番の最初に戻したときでも）。
- ログの各行に、出来事の主体の席を持たせた。ログの窓でプレイヤーを選ぶと、その人の行だけを出す（ラウンドの区切りなど主体のない行は常に出す）。各行の左端に主体の席の色の帯を付けた。
- 横長レイアウトでは、ログの窓が帯の右端（取り消しのボタン）にかぶさっていたため、帯の下から開くようにした。

## 13.5 ロビーから1人で遊ぶ（2026-10-14 追加）

- 以前は URL に `?auto=1&players=1&seed=…` を付けたときだけ1人で遊べた。ローカル（1台で遊ぶ）の人数の選択に「1人」を足し、ロビーから始められるようにした。ヴァリアントも2〜4人と同じく選べる。
- ソロモード専用のルールは実装していない（対象外のまま）。1人のときは、2人用の場（アクションエリア・ラウンド支援ボードの列）で1人だけが進める。これは以前の URL での1人プレイと同じ挙動である。
- オンライン対戦の人数は2〜4人のままとする（`NewGameForm` の `allowSolo` はローカルだけで指定する）。
- 検査：`tests/playout.test.ts` に、1人でヴァリアントをすべて採用した場合（と採用しない場合）の乱択プレイアウトを足した。
- 1人で上級スキルタイル（ヴァリアント）を採用したときは、場に並べる上級スキルタイルを3枚とする（持ち主の指示）。2〜4人は従来どおり人数＋1枚である。山の切り混ぜ（乱数の消費）は変えず、並べる枚数だけが変わる。そのため、以前に URL から始めた1人・上級スキルタイルありのゲームを再生すると、並ぶ枚数が2枚から3枚に変わる（2〜4人のゲームには影響しない）。

## 13.6 音と演出の設定を保存する（2026-10-15 追加）

- 設定の「音」「演出」の入／切は、対局画面を開くたびに入へ戻っていた。そのため、音を切っていても、新しいゲームを始めた直後（キャラクター選択の「あなたが選ぶ番です」）にお知らせ音が鳴っていた。ページを読み直したときや、オンライン対戦の画面に入り直したときも同じであった。
- 2つの入／切を、この端末のブラウザ（localStorage の `sweetlands.view.v1`）に保存し、対局画面を開くときに読み込むようにした（`GameParts.tsx` の `loadViewSettings` / `saveViewSettings`）。端末ごとの便宜であり、共有データやゲームの進行には含めない。読み書きに失敗した場合は既定値（どちらも入）で遊べる。
- 音の入／切は、最初の描画の前に `setSoundEnabled` へ反映する。開始直後の演出の音も止めるためである。
- 検査用の `?noanim` は、保存した値より優先して両方を切にし、保存もしない。
- 確認：Playwright で、音を切ってから新しいゲームを始めた場合と、ページを読み直してから始めた場合に、発音（オシレーターの生成）が0回であることを確かめた。

## 13.7 準備の小窓を畳んで盤面を見る（2026-10-17 追加）

- キャラクターの選択・地図ボードの選択・準備のドラフトの小窓は画面を覆っており、選んでいる間に盤面（メインボード・個人ボードなど）を見られなかった。
- 小窓の見出しの右に「閉じて盤面を見る」を足した（`Dialogs.tsx` の `SetupShell`）。畳んでいる間は、上の帯の下に「（キャラクターの選択／地図ボードの選択／準備のドラフト）を開く」ボタンだけを出し、押すと小窓に戻る。
- 畳んでいる間も、選択そのものは小窓の中でしかできない（盤面の要素は準備の合法手の対象にならないため）。
- 選ぶ人や段階が変わると、小窓は開いた状態に戻る（自分の番が来たときに見落とさないため）。
- 畳んだかどうかは画面だけの状態で、共有データやゲームの進行には含めない。

## 13.8 「何回でも」の支払いをまとめて行う（2026-10-17 追加）

- 「→*」の支払い（例：パス時カードのレオ・レモンドロップ、スカイ・シュガープラム、アレックス・アンバー「基礎資源1 → 2ゴールドを何回でも」）は、1回払うたびに「支払う／もう支払わない」を聞いていた。回数を選んでまとめて払えるようにした。
- 選択肢：従来の `pay`（1回払って、また聞く）と `skip` に加え、`pay:k`（k 回分をまとめて払い、聞き直さずに終える）を足した。k は2から、コストを k 倍しても払える最大の回数まで（上限99）。`pay`・`skip` の ID は変えていないため、以前の手の列もそのまま再生できる。乱数の消費も変えていない。
- 得る効果は、得る資源だけならその数を k 倍にし（`scaleEffs`）、それ以外は k 回並べる（`repeatEffs`）。コストは `scaleCost` で k 倍にする（任意の基礎資源・手札も k 倍の数を選ぶ）。
- 画面：回数の入力（`Band.tsx` の `TimesPanel`）。＋／− と「最大」で回数を選び、「決定」で払う。初期値は0で、1回しか払えないときだけ1を入れておく。「もう支払わない」は従来どおりボタンで出す。
- 検査：`tests/repeat_pay.test.ts`。

## 13.9 内訳の入力の配置を固定する（2026-10-17 追加）

- 基礎資源の内訳の入力は、見出しに今の合計（「払う内訳（合計9／…）」）を含めていたため、数を変えるたびに見出しの長さが変わり、＋／− の位置がずれていた。決定のボタンの文（「合計を…にしてください」）の長さでも折り返しが変わっていた。
- 見出しは数によらない文（「払う内訳：合計3の倍数（21以下）」）にし、今の合計と案内は ＋／− の後ろに置いた。数の欄は等幅数字で幅を固定し、3組の ＋／− はまとめて1行に置く。決定のボタンの文は常に「決定」とし、決定できない理由はボタンの後ろに小さく出す。
- 確認：PC 横長とスマートフォン縦持ちで、数を0から2桁まで変えても ＋ の位置が1pxも動かないことを Playwright で測った。

## 13.10 自分の手番の知らせを大きくする（2026-10-17 追加）

- 自分の手番が来たときの音を、上がる4音を2回、効果音より大きな音量（`TURN_GAIN` = 0.35）で鳴らすようにした。倍音を重ね、スマートフォンの小さなスピーカーでも聞こえやすくした。手番以外の選択（カードの効果の選択など）の音は従来どおり小さく1音である。
- 端末によっては AudioContext が止まったままになるため、鳴らすたびに再開を試みる。
- 設定の「音」を切っていれば鳴らない（13.6）。

## 13.11 準備の選択に確認を挟む（2026-10-17 追加）

- キャラクター・地図ボードの選択と、準備のドラフトのピックは、押しただけで確定していたため誤操作を招きやすかった。押すと「〜を選びます。よろしいですか」の確認の小窓を出し、「選ぶ」で確定、「やめる」で取りやめるようにした。
- 対象：`setupChar`・`setupMap` と、準備のドラフト（`setupPick`）のキャラクター・地図ボード・ラウンド支援駒。キャラボードの確認画面の「このキャラクターを選ぶ」も同じ確認を通る。通常の準備のラウンド支援駒の置き場所（`support`）と、パス時の移動（`passMove`）は対象外のままとした。
- 実装は画面だけで、合法手・選択肢 ID は変えていない（`gestures.ts` の `setupConfirm`。`Move.confirmOk` で実行ボタンの文を「選ぶ」にする）。確認の小窓は `.modal-back.confirm` とし、準備の小窓やキャラボードの確認画面より手前に出す。
- e2e の自動操作（`autoplay.mjs`・`online.mjs`）は、準備の小窓が出ていても確認の小窓には答えるようにした。

## 13.12 通常の準備のラウンド支援駒にも確認を挟む（2026-10-23 追加）

- 13.11 で対象外としていた通常の準備のラウンド支援駒の置き場所（`support`）にも、同じ確認を挟むようにした（持ち主の指示）。パス時の移動（`passMove`）は対象外のままである。

## 13.13 最終ラウンドのパスで基礎資源をゴールドに替える（2026-10-23 追加）

- 第5ラウンドにパスしたとき、残った基礎資源をすべてゴールドに替える（フリーアクション❺「基礎資源1 → 1ゴールド」を自動で行うのと同じ）。基礎資源はゲーム終了時に得点にならず、ゴールドは5につき1勝利点になるため、替えて損をすることはない。
- パス時の効果（基礎資源を1個につき2ゴールドに替えるパス時カードなど）を解決したあと、パスを終える処理（`passDone`）で行う。ログに「残った基礎資源n個をゴールドに替えた」と出す。
- 選択肢 ID と乱数の消費は変えていない。ただし、以前の記録を再生すると、最終得点が以前より高くなる場合がある（以前は替えずに残っていた基礎資源の分）。

## 13.14 同時に起きた効果の処理順を選ぶ（2026-10-23 追加）

持ち主の指示：同時に起きた効果は本来処理順を選べるのに、自動で決まってしまう場合がある。ラウンド開始時の収入のように順番が決まっているものは今のままとする。

切り分けた結果、選ばせずに決まった順で解決していたのは次の3つであった。

1. 建物駒を2個以上置いたとき：置いたヘクスの効果（地形タイル・首都）は置くたびにすぐ解決し、個人ボードの段のボーナスとショップ駒の産業ボーナスは置き終えたあと置いた順に解決していた。
2. 産業ボーナス：印刷されたオートメーションのあと、オートメーション化したカードを列に並んだ順に解決していた。
3. パス時の市民カード：プレイした順に解決していた。

持ち主の判断で、1（ヘクスの効果も含めてまとめる）と2を選べるようにした。3と、収入フェイズ・パス時の①〜⑥の大きな順番は変えない。

- 新しい選択待ち `orderBundles`。効果は由来ごとのまとまり（`Bundle`：ヘクスの効果、段のボーナス、ショップ駒、印刷オートメーション、カード1枚など）で並べ、`bundle:i` で先に解決するものを選ぶ。順番で結果が変わらないとき（まとまりが1つ、またはすべて資源・収入・得点を得るだけ）は尋ねない（`orderEffects` と同じ基準）。
- 建物駒：置いたヘクスの効果（とビスキュイの上方修正の工業2歩）は、置いたときには解決せず、置き終えたあとに段のボーナス・ショップ駒とまとめて処理順を選ぶ。このため、ヘクスの効果で得た資源を、同じ効果の中で次に置く建物駒のコストには使えない。
- 互換性：選択肢の並びが変わるため、`GameConfig.orderChoice` が真のゲームだけで行う。ロビーで作るゲーム（ローカル・オンライン）と自動対戦（`?auto=1`）は真にする。以前の記録（未定義）は従来どおり自動の順で再生する。
- 自動の処理順：帯の右の「処理順：自分で選ぶ／自動」で、席ごとに試合中いつでも切り替えられる。自動の席には、並んだ順（起きた順）の先頭を自動で答える（`autoAnswer`）。答えは手の列に記録されるため、オンラインでも全員が同じ結果を再生する。切り替えはこの端末のブラウザに保存する（`sweetlands.orderAuto.v1`、席の番号の配列）。

## 13.15 カードを引く手の前に確認を挟む（2026-10-23 追加）

- 市民カードを引く（山札から手札に加える）手や、市民デッキの中を探す手は、新しい情報が出るため、そのあとはその手とそれより前の手を取り消せない（`history.ts` の `isCheckpoint`）。押す前に「この操作で市民カードを引きます。引いたあとは、この操作とそれより前の操作を取り消せなくなります。よろしいですか」の確認を出し、「進める」で行う。探す手は「市民デッキの中を見ます」の文にする。
- 見分け方：押した手をエンジンで仮に進め、選んだ人の市民カードを引く出来事（`card`・`draw`）か探す出来事（`search`）が起きるか、探す選択待ちに入るかで判断する（`interaction.tsx` の `drawsCard`）。ルールを画面で作り直さず、判定はエンジンに任せる。仮に進められない手は確認しない。
- 自動の回答（候補が1つだけの自動、処理順の自動など）は確認を出さない。合法手・選択肢 ID は変えていない。
- 検査：`tests/draw_confirm.test.ts`。
- e2e の自動操作（13.14 の補足、2026-10-23）：帯の「処理順」ボタンは手を進めない設定のボタンのため、`autoplay.mjs`・`online.mjs` では操作の候補から外し、3%の確率でだけ押す。候補に含めていたときは、パスしかできない局面で処理順ボタンばかり押してパスが選ばれず、止まったと判定されることがあった（mouse 111）。

## 13.16 都市の囲みで道駒が見えにくい（2026-10-23）

- 地図の都市の囲み（破線）をヘクスの辺の上に、しかも道駒より手前に描いていたため、都市ができると、その辺に置いた道駒が破線に隠れて見分けにくかった。
- 都市の囲みはヘクスを中心へ0.8倍に縮めた形で描き（`MapBoard.tsx` の `insetPointsOf`、`CITY_INSET`）、辺から離した。道駒は都市の囲みより手前に描く。

## 13.17 取り消した手のやり直し（2026-10-23 追加）

- ローカル（1台で遊ぶ。1人で遊ぶときを含む）で、取り消した手を1手ずつ進め直せるようにした（持ち主の指示）。帯の「やり直す」ボタン、または Ctrl+Y（Ctrl+Shift+Z）。
- 取り消した手（1手の取り消し・手番の最初に戻る）は、進め直す順に積んでおく（`Inner.redo`）。取り消した手は同じ局面から同じ結果になる（乱数・山札も同じ）ため、そのまま適用する。
- 取り消したあとに別の手を選ぶと、残りの進め直しは捨てる。同じ手を選んだとき（自動の回答を含む）は、進め直しを1つ使ったものとして残りを保つ。
- 進め直している途中（まだ進め直せる手が残っている間）は、自動の回答をしない（続けて進め直せるように）。
- 取り消せない手（チェックポイント）より前には、これまでどおり戻れない。オンライン対戦には付けていない。
- 取り消し・やり直しの処理は React から切り離した純粋関数（`useGame.ts` の `applyInner`・`undoInner`・`undoAllInner`・`redoInner`）にし、`tests/redo.test.ts` で確かめる。

## 13.18 リザルトの得点の演出は1回目だけ（2026-10-23 追加）

- リザルトの最終得点は1行ずつ出す演出がある。「最終盤面を見る」「リプレイを見る」から戻ったときにも毎回演出していたため、テンポが悪かった（持ち主の指摘）。
- 同じゲーム（シード・手の数・名前が同じ）のリザルトは、演出を1回目だけにし、2回目からは最初から全部出す（`Result.tsx` の `animKey`）。見せたゲームは画面を開いている間と、このタブのセッションストレージ（`sweetlands.resultShown.v1`、直近20件）に覚える。ローカルとオンラインの両方に効く。

## 13.19 思考時間・オートメーション化したカード・捨て札の表示（2026-10-30 追加）

持ち主の指示による UI の改善。ルールと合法手、選択肢 ID は変えていない。

思考時間：

- プレイヤーの一覧（横長レイアウトの上部、スマートフォンの「みんな」）に、各プレイヤーの思考時間（ゲームの開始からの合計）を出す。いま選択を待っている人は太字で、1秒ごとに数え続ける。
- 数えるのは「その人の選択を待っていた時間」である（`useGame.ts` の `thinkers`）。同時に選べる選択待ち（手札のドラフト）では、まだ答えていない全員を数える。準備（キャラクター・地図の選択など）の時間も含む。
- ローカル：局面が変わるたびに、それまで選択を待っていた席に経過時間を足す（`useLocalClock`）。保存した対局の続きを開いたときに続きから数えられるよう、この端末のブラウザに保存する（`sweetlands.think.v1`、設定とシードで対局を見分ける）。
- オンライン：手を送った人が、自分の画面で測った「自分の選択待ちが始まってから送るまで」の時間を、共有ドキュメントの `think`（席ごとのミリ秒）に足して書く（`useOnlineGame.ts`）。測るのは1つの時計だけなので、端末の時計のずれは入らない。ほかの人の分は、届いた `think` に、最後に盤面が変わってからの経過を足して表示する（通信の遅れのぶん、少しずれる）。以前のドキュメント（`think` なし）は0から数える。
- 再読み込みしたときは、それまでに送った分は残り、選択待ちの途中で測っていた分（まだ送っていない分）は失われる。

オートメーション化したカード：

- 個人ボードの産業列のカード（アイコン）に、マウスを重ねる／長押しすると、カード全体（即時能力・タグを含む）を拡大表示する。以前は産業列全体の小窓で、名前とオートメーション能力の文だけを出していた。
- 横長レイアウトの「プレイしたカード」の一覧に、オートメーション化したカードを産業列ごとに表面つきで加えた。スマートフォンでは、キャラボードの下に「オートメーション化したカード」の展開ボタンを置いた。

捨て札：

- 共通サプライの捨て札置き場をクリックすると、捨て札を新しい順に表面つきで並べた一覧を開く（各カードはマウスを重ねる／長押しで拡大表示）。捨て札は表向きで、誰が見てもよい情報である。
- カードを捨てる操作の置き先になっているときは、これまでどおりの置き場（ここに置いて捨てる）として出す。
- 展開した窓（Fold）は、画面より広くならないようにした（狭い画面では画面の幅に合わせる）。

e2e の自動操作（2026-10-30）：

- `autoplay.mjs` は●印の展開ボタン（フリーアクションなど）をときどき開き、そのまま閉じない。開いた窓が盤面の対象（マイルストーンなど）を覆うと、クリックが窓に吸われて手が進まず、止まったと判定されていた（mouse 3、4人、上方修正あり）。押したい要素がほかの展開の窓に覆われているときは、人と同じく開いている窓を閉じてから押すようにした（`uncover`）。押したい要素が窓の中にあるときは閉じない。

思考時間の不具合（2026-10-30、持ち主の指摘「一人目の最初の選択が数えられていない」）：

- オンラインで、手を送るときの土台に「最後に届いた共有ドキュメントの `think`」を使っていた。自分の書き込みが自分の画面へ戻ってくる前に続けて次の手を送ると（選んだ直後の自動の回答、確認のあとの続きの選択など）、2手目は1手目で足す前の古い値を土台にし、1手目で足した時間を上書きで消していた。ゲームの最初は選択のあとに続けて書き込みやすく、一人目の最初の選択待ちの時間が消えやすかった。
- 手元の値（`thinkRef`）を、届いた値と自分が送った値を席ごとに大きいほうで合わせて持ち（`mergeThink`）、これに足して送るようにした。同時の選択待ち（`transact`）でも、読んだ値と手元の値を同じく合わせる。思考時間は増えるだけ（取り消しでも減らさない）なので、大きいほうを取れば新しい値を取りこぼさない。
- 偽 DB には本番の通信の遅れを真似る `&fakelag=<ミリ秒>`（自分の書き込みが自分の画面へ戻るのを遅らせる）を足した。`e2e/think.mjs` で、最初の選択待ちに3秒考えて続けて2手打ち、その3秒が `think` に残ることを確かめる（修正前は0.4秒しか残らなかった）。

## 13.20 観戦モード（2026-10-30 追加）

持ち主の指示による。ルールと合法手、選択肢 ID、共有ドキュメントの形は変えていない。

- オンラインのロビーで、席がすべて埋まって進行中のゲームには「観戦する」ボタンを出す（以前は「観戦はできません」と出していた）。席を持たない人（利用者を確認できず閲覧だけの人を含む）が押すと、観戦の画面になる。
- 観戦者は共有ドキュメントの手の列を再生して見るだけで、書き込まない（`useOnlineGame` を席なしで使う。選択待ちになることがないため、書き込みは起きない）。
- 伏せた情報は誰の分も見せない。画面の部品は「見ている席（own）と持ち主が違えば伏せる」作りのため、観戦では own を -1 にする（`Game` の `spectator`）。手札は裏向きの枚数だけ、引いたカードのログと演出は伏せ字、候補のカード（デッキの検索・手札のドラフト）は出さない。
- 画面の主役の席（「自分」の場として出す席、`viewer`）は、選択待ちの人を追いかける。ほかの人の場も「みんな」から選んで見られる（「選んでいる人に戻る」で戻る）。
- 観戦中であることは、横長レイアウトでは上部の「観戦中」の札で、どのレイアウトでも帯の文の頭（「観戦中：〇〇さんの手番です」）で示す。
- 観戦者は思考時間を書かない。プレイヤーの一覧には、届いた思考時間をほかの人と同じように表示する。
- ゲームが終わると、観戦者にもリザルトを出す。
- 検査：`e2e/online.mjs` は観戦者のページを1つ開き、5手ごとと最後に、盤面がほかの全員と一致すること、誰の手札の中身も DOM にないこと、操作できる要素がないことを確かめる。
