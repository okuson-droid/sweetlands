# decisions.md 追補 §13：機能の追加（2026-10-12）

準拠：`SweetLands_rules.md`（v1.0）と `SweetLands_rules_v1.1.md`（v1.1）。ルールとルールエンジンの判定は変えていない。選択肢 ID と乱数の消費も変えていない。

## 13.1 リプレイと最終盤面

- オンライン対戦のリザルトの「リプレイを見る」は何もしなかった（`Online.tsx` で空の処理を渡していた）。ローカル対戦と同じ `ReplayScreen` を開くようにした。
- リザルトに「最終盤面を見る」を足した。リプレイ画面を最後の手の位置で開く。「リプレイを見る」は最初（0手目）から開く。
- `ReplayScreen` に開く位置（`at: 'start' | 'end'`）を足した。

## 13.2 対局中の集計

- 個人ボードのキャラクター名の行の下に、次の集計を出す（`TallyLine`）。
  - 置いた地形タイルの枚数：麦畑・森林・鉱山・海ごと。特殊地形タイルは置いたときだけ出す。
  - 置いた道駒の本数。
  - プレイしたカードの枚数：産業タグ（農業・林業・鉱業）ごと。オートメーション化したカードも含める。
- 産業タグは、カードの産業そのもので数える。オールマイティのカードは農業・林業・鉱業に重ねず、別の数として出す（ある場合のみ）。産業タグのないカードも、ある場合のみ別に出す。時計塔駒の条件の判定（`playedCount`）はオールマイティを各産業に含めるが、集計の表示は重複を避けるため分けた。
- 集計は `queries.ts` の `tally` で計算する（純粋関数。`tests/rules.test.ts` で検査する）。

## 13.3 手番の最初に戻る

- 1手の取り消しとは別に、帯に「手番の最初に戻る」を足した。取り消せる手が2手以上あるときだけ出す。
- 戻る先は、取り消せる範囲の先頭（チェックポイント）である。手番が変わるとチェックポイントになるため、通常は手番の最初に戻る。手番の途中で山札を引くなど新しい情報が出た場合は、その時点より前には戻らない（1手の取り消しと同じ制約）。
- `GameSession.undoAll` をローカル（`useGame`）とオンライン（`useOnlineGame`）の両方に足した。オンラインでは手の列をチェックポイントまで縮めて送る。
- e2e の自動操作は、このボタンを1手の取り消しと同じく押さない。

## 13.4 ログ

- 取り消した手のログは、以前は取り消し線を引いて残していた。手の列が縮んだら、それより後の手で出た行を消すようにした（1手の取り消しでも、手番の最初に戻したときでも）。
- ログの各行に、出来事の主体の席を持たせた。ログの窓でプレイヤーを選ぶと、その人の行だけを出す（ラウンドの区切りなど主体のない行は常に出す）。各行の左端に主体の席の色の帯を付けた。
- 横長レイアウトでは、ログの窓が帯の右端（取り消しのボタン）にかぶさっていたため、帯の下から開くようにした。

## 13.5 ロビーから1人で遊ぶ（2026-10-14 追加）

- 以前は URL に `?auto=1&players=1&seed=…` を付けたときだけ1人で遊べた。ローカル（1台で遊ぶ）の人数の選択に「1人」を足し、ロビーから始められるようにした。ヴァリアントも2〜4人と同じく選べる。
- ソロモード専用のルールは実装していない（対象外のまま）。1人のときは、2人用の場（アクションエリア・ラウンド支援ボードの列）で1人だけが進める。これは以前の URL での1人プレイと同じ挙動である。
- オンライン対戦の人数は2〜4人のままとする（`NewGameForm` の `allowSolo` はローカルだけで指定する）。
- 検査：`tests/playout.test.ts` に、1人でヴァリアントをすべて採用した場合（と採用しない場合）の乱択プレイアウトを足した。
- 1人で上級スキルタイル（ヴァリアント）を採用したときは、場に並べる上級スキルタイルを3枚とする（持ち主の指示）。2〜4人は従来どおり人数＋1枚である。山の切り混ぜ（乱数の消費）は変えず、並べる枚数だけが変わる。そのため、以前に URL から始めた1人・上級スキルタイルありのゲームを再生すると、並ぶ枚数が2枚から3枚に変わる（2〜4人のゲームには影響しない）。

## 13.6 音と演出の設定を保存する（2026-10-15 追加）

- 設定の「音」「演出」の入／切は、対局画面を開くたびに入へ戻っていた。そのため、音を切っていても、新しいゲームを始めた直後（キャラクター選択の「あなたが選ぶ番です」）にお知らせ音が鳴っていた。ページを読み直したときや、オンライン対戦の画面に入り直したときも同じであった。
- 2つの入／切を、この端末のブラウザ（localStorage の `sweetlands.view.v1`）に保存し、対局画面を開くときに読み込むようにした（`GameParts.tsx` の `loadViewSettings` / `saveViewSettings`）。端末ごとの便宜であり、共有データやゲームの進行には含めない。読み書きに失敗した場合は既定値（どちらも入）で遊べる。
- 音の入／切は、最初の描画の前に `setSoundEnabled` へ反映する。開始直後の演出の音も止めるためである。
- 検査用の `?noanim` は、保存した値より優先して両方を切にし、保存もしない。
- 確認：Playwright で、音を切ってから新しいゲームを始めた場合と、ページを読み直してから始めた場合に、発音（オシレーターの生成）が0回であることを確かめた。

## 13.7 準備の小窓を畳んで盤面を見る（2026-10-17 追加）

- キャラクターの選択・地図ボードの選択・準備のドラフトの小窓は画面を覆っており、選んでいる間に盤面（メインボード・個人ボードなど）を見られなかった。
- 小窓の見出しの右に「閉じて盤面を見る」を足した（`Dialogs.tsx` の `SetupShell`）。畳んでいる間は、上の帯の下に「（キャラクターの選択／地図ボードの選択／準備のドラフト）を開く」ボタンだけを出し、押すと小窓に戻る。
- 畳んでいる間も、選択そのものは小窓の中でしかできない（盤面の要素は準備の合法手の対象にならないため）。
- 選ぶ人や段階が変わると、小窓は開いた状態に戻る（自分の番が来たときに見落とさないため）。
- 畳んだかどうかは画面だけの状態で、共有データやゲームの進行には含めない。

## 13.8 「何回でも」の支払いをまとめて行う（2026-10-17 追加）

- 「→*」の支払い（例：パス時カードのレオ・レモンドロップ、スカイ・シュガープラム、アレックス・アンバー「基礎資源1 → 2ゴールドを何回でも」）は、1回払うたびに「支払う／もう支払わない」を聞いていた。回数を選んでまとめて払えるようにした。
- 選択肢：従来の `pay`（1回払って、また聞く）と `skip` に加え、`pay:k`（k 回分をまとめて払い、聞き直さずに終える）を足した。k は2から、コストを k 倍しても払える最大の回数まで（上限99）。`pay`・`skip` の ID は変えていないため、以前の手の列もそのまま再生できる。乱数の消費も変えていない。
- 得る効果は、得る資源だけならその数を k 倍にし（`scaleEffs`）、それ以外は k 回並べる（`repeatEffs`）。コストは `scaleCost` で k 倍にする（任意の基礎資源・手札も k 倍の数を選ぶ）。
- 画面：回数の入力（`Band.tsx` の `TimesPanel`）。＋／− と「最大」で回数を選び、「決定」で払う。初期値は0で、1回しか払えないときだけ1を入れておく。「もう支払わない」は従来どおりボタンで出す。
- 検査：`tests/repeat_pay.test.ts`。

## 13.9 内訳の入力の配置を固定する（2026-10-17 追加）

- 基礎資源の内訳の入力は、見出しに今の合計（「払う内訳（合計9／…）」）を含めていたため、数を変えるたびに見出しの長さが変わり、＋／− の位置がずれていた。決定のボタンの文（「合計を…にしてください」）の長さでも折り返しが変わっていた。
- 見出しは数によらない文（「払う内訳：合計3の倍数（21以下）」）にし、今の合計と案内は ＋／− の後ろに置いた。数の欄は等幅数字で幅を固定し、3組の ＋／− はまとめて1行に置く。決定のボタンの文は常に「決定」とし、決定できない理由はボタンの後ろに小さく出す。
- 確認：PC 横長とスマートフォン縦持ちで、数を0から2桁まで変えても ＋ の位置が1pxも動かないことを Playwright で測った。

## 13.10 自分の手番の知らせを大きくする（2026-10-17 追加）

- 自分の手番が来たときの音を、上がる4音を2回、効果音より大きな音量（`TURN_GAIN` = 0.35）で鳴らすようにした。倍音を重ね、スマートフォンの小さなスピーカーでも聞こえやすくした。手番以外の選択（カードの効果の選択など）の音は従来どおり小さく1音である。
- 端末によっては AudioContext が止まったままになるため、鳴らすたびに再開を試みる。
- 設定の「音」を切っていれば鳴らない（13.6）。

## 13.11 準備の選択に確認を挟む（2026-10-17 追加）

- キャラクター・地図ボードの選択と、準備のドラフトのピックは、押しただけで確定していたため誤操作を招きやすかった。押すと「〜を選びます。よろしいですか」の確認の小窓を出し、「選ぶ」で確定、「やめる」で取りやめるようにした。
- 対象：`setupChar`・`setupMap` と、準備のドラフト（`setupPick`）のキャラクター・地図ボード・ラウンド支援駒。キャラボードの確認画面の「このキャラクターを選ぶ」も同じ確認を通る。通常の準備のラウンド支援駒の置き場所（`support`）と、パス時の移動（`passMove`）は対象外のままとした。
- 実装は画面だけで、合法手・選択肢 ID は変えていない（`gestures.ts` の `setupConfirm`。`Move.confirmOk` で実行ボタンの文を「選ぶ」にする）。確認の小窓は `.modal-back.confirm` とし、準備の小窓やキャラボードの確認画面より手前に出す。
- e2e の自動操作（`autoplay.mjs`・`online.mjs`）は、準備の小窓が出ていても確認の小窓には答えるようにした。
