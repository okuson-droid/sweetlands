# decisions.md 追補 §15：両替のフリーアクションの一括と、内訳の初期値（2026-10-13）

準拠：`SweetLands_rules.md`（v1.0）と `SweetLands_rules_v1.1.md`（v1.1）。ルールは変えていない。一括の両替は、同じフリーアクションを繰り返し使った場合と同じ結果になる（❸❺❻はラウンド内の回数に制限がない）。

## 15.1 両替の一括

- 対象は次の3つである。いずれも、1回の操作で何単位分でもまとめて行う。
  - ❸ 4ゴールド → 任意の基礎資源1：得る基礎資源の内訳を入力する。合計は1以上、所持ゴールド÷4（切り捨て）以下。決定したとき、合計×4ゴールドを払う。
  - ❺ 基礎資源1 → 1ゴールド：払う基礎資源の内訳を入力する。合計は1以上、所持数以下。払った個数だけゴールドを得る。
  - ❻ 基礎資源3 → 任意の基礎資源1：払う基礎資源の内訳（合計3n）を入力し、続けて得る基礎資源の内訳（合計n）を入力する。
- エンジン：
  - ❺❻は `pay` タスクの ctx に `bulk`（1単位の個数）を持たせる。`payBasic` の選択肢は、合計が `bulk` の倍数になる内訳すべてである（`bulkCombos`）。払った単位数を `ctx.times` に覚え、`then` の効果を単位数倍にして積む（`scaleEffs`）。
  - ❸は `anyBasic` タスクの ctx に `goldEach`（1個あたりのゴールド）を持たせる。選択肢は合計1〜（所持ゴールド÷goldEach）の内訳すべてで、決定したときにゴールドを払う。以前は❸を選んだ時点で4ゴールドを払っていたが、払う額が内訳の決定まで決まらないため、払う時点を後ろへ移した。
- 選択肢 ID：❸❺❻の ID と、内訳の ID（`basic:麦-木材-鉄`）の付け方は変えていない。1単位分の内訳は以前と同じ ID で選べ、結果も以前と同じであるため、以前の手の列はそのまま再生できる。乱数の消費も変えていない。
- 支払いの内訳の自動化（設定）は、一括の支払いには答えない。払う数はプレイヤーが決めるものだからである。

## 15.2 内訳の入力の初期値

- 基礎資源の内訳の入力（`Band.tsx` の `SplitPanel`）は、以前は先頭の選択肢の内訳を初期値として入れていた。初期値を0にした。選択肢が1つしかないときだけ、その内訳を入れておく。
- 合計が1通りに決まらない入力（15.1）のため、合計の条件は選択肢から読み取って示す（「合計9／3の倍数（9以下）」など）。決定できないときは、合計の条件を満たしていないのか、持っている数を超えているのかをボタンに示す。

## 15.3 自動操作（e2e）

- 初期値が0になったため、`e2e/split.mjs` の `stepSplit` で、候補の内訳のうちいまの値にいちばん近いものへ＋／−を1回ずつ押して合わせる。`autoplay.mjs` と `online.mjs` で共用する。
- 候補の内訳は、選択待ちの本人の画面に限り `window.__sl.splits` に出す（本人の手持ちから決まる情報だけで、他人の手札は含まない）。
