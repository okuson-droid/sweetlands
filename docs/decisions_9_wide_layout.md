# decisions.md 追補 §9：横長（PC）レイアウトの改訂（2026-10-11）

設計は `ui_design_21_wide_layout.md`（UI設計書 追補 §21）。ここには実装上の判断を記録する。ルールとゲーム処理（`src/game/`）は変更していない。

## 9.1 構成

- `src/ui/Game.tsx` の `WideLayout` を置き換えた。旧配置（上半分＝共通の場、下半分＝自分の場、境目をドラッグで動かす）は削除した。スマートフォン横持ちの `NarrowLayout` は変更していない。
- 新しい部品：
  - `components/Fold.tsx`：クリックで展開する見出し。中身は `.game` 直下へポータルで描き、盤面のスクロール枠や `zoom` に切られないようにする。`force`（操作の対象になったら自動で開く）と `hint`（使える手が中にあるときの●印）を持つ。
  - `MainBoard.tsx`：`FreeActions`・`SkillPiles`・`SupportBoard`・`SideStrip`・`ProsBoard` を切り出した。`MainBoard` は `freeSlot`（フリーアクション列の差し替え）と `prosExtra`（繁栄トラックの拡大ボタン）を受け取る。
  - `HandBar.tsx`：`HandRow`（重ねた手札と覗き窓）・`MineSupply`・`SharedSupply`（`contextual` で地形タイルと道を置けるときだけ出す）を追加した。狭い画面用の `HandBar` はそのまま残す。
  - `PersonalBoard.tsx`：`withTableau` で手元の欄を外せるようにし、展開用の `TableauCards` を追加した。
- スタイルは `src/ui/wide.css` に集めた（`.game.wide` の下）。倍率は CSS 変数 `--mainzoom`（0.76）・`--pzoom`（1.16）・`--cardzoom`（1.7）。

## 9.2 判断

- 展開の自動化：ラウンド支援駒・特殊地形タイル・手元への置き先・プレイしたカードのオートメーション化・スキルタイルの獲得では、対象になった時点で自動で開く。フリーアクションは手番中ほぼ常に使えるため自動では開かず●印だけを出し、ディスクや手札の置き先になったときだけ開く。判定は合法手（`aff.clicks`・`aff.drags` のキー）だけから導く（設計原則3）。
- 展開したプレイ済みカードは持ち上げられる（`tableau:ID`）。オートメーション化で、手元のカードを産業列へ動かすため。初版の試作では絵だけを並べていて動かせず、受け入れ検査の新しい項目で見つかった。
- 手札の覗き窓：合わせたカードを前に出す方式は、前に出たカードが右隣を覆い、右へなぞって次のカードへ移れないため採らなかった。カードは動かさず、手札の上の決まった位置に表面と文章を出す。覗き窓は `pointer-events: none`。
- 手札にカーソルがあるあいだは、拡大表示の小窓（`.zoom`）を CSS の `:has()` で隠す。覗き窓と同じ内容が重なって読めなくなるため。
- 拡大表示は、その盤面と同じ部品をもう一度描く（地図なら `MapBoard`）。そのため拡大中もそのまま操作でき、光る対象も同じになる。下の元の盤面は覆われるだけで、外さない。
- 画面確認用の URL 引数を足した：`?open=support,free,skills,special,tableau`（その展開を最初から開く）、`?enlarge=map|char|industry|pros`（最初から拡大する）。e2e のスクリーンショット専用で、遊ぶときには使わない。

## 9.3 受け入れ検査の追加（`e2e/autoplay.mjs`）

- `__sl.sources`（いま使える手の、所作の出発点と置き先のキー）を観測点に足した。
- unreachable 検査：使える手が、見えている要素にも、●印の付いた展開ボタンの中にもないものを記録する。合法手の一覧は描画の直後に更新されるため、手が進まないまま 150ms あけた2回の読み取りで、どちらでも見つからない手だけを記録する。
- 自動プレイヤーは、●印の付いた展開ボタンをときどき人のように開く（開かないと、畳んだ中の手を一度も試さないため）。
