# 対話プレイ（AI の打ち手同士の対局）の回し方

AI（Claude）の打ち手が1席ずつ受け持ち、コマンド（`tools/play/`）を通して対局する手順と、コマンドの約束事である。
都市開発ボードゲーム（okuson-droid/city-boardgame）の対話プレイの考え方と運用を、このゲームに合わせて移した（2026-11-16）。

| ファイル | 内容 |
|---|---|
| `player-brief.md` | 打ち手への指示（3KB 以内）。`<席>`・`<作業ディレクトリ>`・`<リポジトリ>` を埋めて渡す |
| `round-task.md` | 各ラウンドの終わりに、得点を増やす戦術と思考リソースの省力化の提案（`.play/proposals/P<席>-R<ラウンド>.md`）を書かせるときの追加の務め。作業ディレクトリに写し、起動の指示で読ませる |
| `goals-task.md` | 各ラウンドの初めに、そのラウンドの目標（`.play/goals/P<席>-R<ラウンド>.md`）を書かせ、終わりに目標と結果を照らし合わせさせるときの追加の務め。手番ごとの思考を書かせる指示は、2026-11-17 に打ち手のモデルの安全装置（reasoning_extraction）に止められたため使わない |
| `knowledge-play.md` | 打ち手が対局の前に読む知見の要約（3KB 以内）。作業ディレクトリに写す |
| `<日付>/` | 対局の記録（`game.json`）・各席の知見（`insights/`）・振り返り（`reflect/`）・最終得点と経緯（`README.md`）。打ち手には読ませない |

## 手順

1. ビルドする：リポジトリで `npm run play:build`。`dist-play/cli.js`（1ファイル）ができる。配布用のビルド（`npm run build`、`dist/`）には含まれない。
2. 作業ディレクトリをリポジトリの外に1つ作る（例：スクラッチパッドの `play-<日付>/`）。全席がこのディレクトリで起動し、記録 `.play/game.json` を共有する。リポジトリの外に置くのは、打ち手にリポジトリのファイル（実装・CLAUDE.md）を読ませないためである。ただし同じセッションから Agent で起動した打ち手には、リポジトリの CLAUDE.md が自動で入る。
3. 対局を作る：作業ディレクトリで `node <リポジトリ>/dist-play/cli.js new --players 3 --seed <シード>`。設定は通常ルール（ヴァリアントなし、効果の処理順を選ぶ版。オンライン版のロビーの既定と同じ）。
3-2. `knowledge-play.md` を作業ディレクトリに写す。
4. 席ごとに打ち手を起動する：`player-brief.md` の `<席>`・`<作業ディレクトリ>`・`<リポジトリ>` を埋めた全文に「いまのラウンド R」を添えて渡す。準備（キャラクター・地図・ラウンド支援駒）は第1ラウンドに含める。
5. ラウンドごとに作り直す：打ち手は `wait --round R` が「ラウンド R は終わった」と出したら、ノート（`.play/notes/P<席>.md`、1.5KB 以内）を書いて終える。回す側は R＋1 を添えて新しい打ち手を起動し、新しい打ち手はノートと `resume` から続ける。会話の履歴は持ち越さない。ラウンドの終わりの「手札を1枚残す」はそのラウンドの打ち手が選び、次のラウンドの収入で出る選択（支援タイルの基礎資源の内訳など）は次の打ち手が選ぶ。
6. 終局後に回収する：`.play/game.json` を `docs/playtest/<日付>/game.json` に、各席の知見（`.play/insights/P<席>.md`、2KB 以内）を `docs/playtest/<日付>/insights/` に置き、最終得点と内訳（`score` の出力）と経緯を `docs/playtest/<日付>/README.md` に書く。
7. 振り返り：終局後、席ごとに打ち手を1人起動し、記録（`log`・`score`・`show --player`）と全席の知見から、繁栄トラックなど項目ごとの取りこぼしと、目標点（例：300点）に届く案を `.play/reflect/P<席>.md`（3KB 以内）に書かせる。回す側は重なった教訓を `knowledge-play.md` にまとめる（3KB を越えたら古い内容を削るか統合する）。

## コマンド

`node <リポジトリ>/dist-play/cli.js --help` に全文がある。要点：

| コマンド | 内容 |
|---|---|
| `new --players N --seed S` | 記録を作る（既にあれば `--force` のときだけ上書き） |
| `show [--seat N] [--only 欄] [--player N]` | 局面。欄は status・players・areas・shared・self・map・hand・options |
| `move <選択>... --seat N [--then-wait] [--round R]` | 選択肢 ID か番号を順に当てる。`--dry-run` は記録を変えない下見 |
| `wait --seat N [--round R] [--timeout 秒]` | 番を待つ（既定100秒） |
| `ref [--only 欄] [--card ID]` | 対局中に変わらない文言（ルールの要約・ID の型・エリア・キャラクター・個人ボード・トラック・タイル・地図の面） |
| `resume --seat N` | 作り直した打ち手が1回で状況をつかむための出力 |
| `score` / `log` | 得点の内訳／記録の選択の一覧 |

## 約束事

- 1回の呼び出しで完結し、入力待ちを作らない。成功は終了コード0、失敗は1。失敗の文は標準出力にだけ出す（標準エラーにも出すと打ち手の道具では2回見えるため）。
- 記録は JSON 1つ（既定 `.play/game.json`、`--file` で指定）で、`{ format, seed, config, moves }` を持つ。局面は常に `replay` と同じ手順（`createGame` から `applyMove` を順に当てる）で作り、GameState は保存しない。書き込みは一時ファイルからの置き換えで行い、書きかけを他の席が読まないようにする。
- ルールは再実装しない。合法手は `getOptions`（同時に選ぶ場面は `viewFor`）、進行は `applyMove`、派生値は `queries.ts`、得点は `scoring.ts` の `finalScores`、選べない理由の文は `explain.ts` だけから得る。
- `move` は1つでも選べなければ記録を一切変えず、失敗の文の2行目にその段の選択肢 ID を出す。`--seat` の席が選択待ちでなければ失敗する。
- 道駒の辺の ID（`edge:頂点座標|頂点座標`）は読めないため、コマンドでは `edge:<行>,<列>:<向き>`（向き e・w・ne・nw・se・sw）と見せ、受け付ける。同じ辺はどちらのヘクスからも書ける。記録にはエンジンの ID を入れる。辺の呼び名は `queries.ts` の `edgeInfo`・`edgeAt`。
- 非公開情報：視点（`--seat`）以外の手札の中身と、山札の順序は出さない。選択肢は選択待ちの席の視点でだけ出す。他の席の手番の要約では、山札を探す・ドラフト・手札を残す選択を伏せる（`ui/playback.ts` の `redact` と同じ範囲）。山札の中身が見える選択肢（探す・ドラフト）は、表示の順をラベル順にして山札の順序を見せない。番号はこの表示の順である。資源・収入・手札の枚数・プレイしたカード・捨てたカードは公開である。
- 既定の出力は短くする。対局中に変わらない文言は `ref` に分け、`wait`・`move` は他の席の手番を1手番1行・自分の1行・置かれたスペース・選択肢だけを出す。行動を選ぶ場面では、選べないエリアと手札をその理由（`explain.ts`）ごとにまとめて1行で出す。
- `wait` の他の席の要約は、席ごとに前回どこまで見せたか（記録と同じディレクトリの `seen-P<席>.json`）から出す。`--round R` は局面がラウンド R より先なら番を待たずに「ラウンド R は終わった」と出す。`wait` と `--then-wait` の既定の時間切れは100秒で、打ち手の道具の上限（約120秒）より短い。
- 判断の余地がない段は自動で進める（2026-11-16 の3局目の提案、持ち主の採用）：その席の番の間、選択肢が1つだけの段は `move` の各指定の後と、`wait` で番が来たところで進め、記録に普通の手として書く（出力に「（自動）」「自動で選んだ（1択）」と出す）。`move` に `order:auto` を並べると、それ以後の効果の順番を選ぶ段（bundle・eff）を表示の先頭から選ぶ。自動で進めた段と同じ ID を打ち手が続けて書いていても、失敗にせず読み飛ばす（4局目の提案）。選ぶのは `getOptions` の選択肢だけで、ルールの判断はしない。オンライン版の画面はこの自動の進行をしない。
- 道駒の置き場所が9個以上のときは、タイルが裏返る辺と港・追加ドローエリアとの境の辺だけを全文で出し、残りは ID だけを1行にまとめる（4局目の提案）。
- 行動を選ぶ段（`turn`）の選択肢は、既定ではエリア・コピー先・カード・フリップ・取れるもの（マイルストーン・時計塔）・フリーアクションの種類ごとに1行へ畳み、番号を出さない（ID で選ぶ。番号は全文の順のまま受け付ける）。番号つきの全文は `--full`。
- `move --dry-run` は、山札・乱数に触れる手（引く・探す・混ぜ直す）の手前で止め、その先を見せない。
- 得点：`score` は `finalScores` をそのまま出す。終局前は「いま終わったときの計算」であり、この先のパス時の得点と収入は含まない。
- 選択肢のラベル（`Option.label`）は、ラベルだけで何を選ぶ手か分かる文にする（払うもの・得るもの・対象の名前）。内部の識別子（カード ID・辺の頂点座標・英字の内部名）を含めない（`tests/play_cli.test.ts` が乱択プレイアウトで確かめる）。選択肢 ID の付け方と乱数の消費順は変えない。
- ルールの要約（`ref --only rules`）はエンジンの実装を読んで書いたもので、ルール本文の代わりではない。食い違えば選択肢が正である。

## 確かめていないこと

- 4人戦と、ヴァリアント（特に同時に選ぶ手札のドラフト）を採用した対局での運用。記録の書き込みは「読んだ後に記録が変わっていたら失敗する」だけで、同時に2席が書く場面の排他はしていない。
