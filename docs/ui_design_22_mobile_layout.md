# UI設計書 追補 §22：スマートフォンのレイアウト（縦持ち・横持ち）

準拠：`ui_design.md`（第3版）、`ui_design_21_wide_layout.md`、`decisions.md`
状態：ユーザー承認済み（2026-10-13）。レイアウト案（縦持ち 案A〜C、横持ち 案D・E）を画像で示し、ユーザーが「縦持ち＝案A、横持ち＝案D」を採用した。
位置づけ：この追補は `ui_design.md` §4.2（スマートフォン横持ち）を置き換え、§1・§19 の「縦持ちでは横向きの案内だけを出す」を改める。PC の横長レイアウト（§21）は変えない。ルールとゲーム処理は変えない。

## 22.1 レイアウトの切り替え

- 画面の幅が 1280px 以上かつ高さが 600px 以上なら横長（§21）。それ以外は、高さが幅より大きければ縦持ち、そうでなければ横持ちとする。
- 端末を回すと、その場でレイアウトが切り替わる。「横向きにしてください」の案内は廃止した。
- 想定する画面：縦持ち 390×844、横持ち 844×390（ブラウザの枠を除いた表示域）。より小さい画面では、盤面を縮めるか、枠の中をスクロールして収める。

## 22.2 縦持ち（案A：盤面を画面いっぱいに＋下タブ）

```
┌──────────────────────────┐
│ R2 アクション［いちご］［みかん］［ぶどう］  ≡ │ 上の札（≡：ログ・設定・全画面・ロビー）
│ 資源（G 麦 木 鉄 ダイヤ ディスク 手札）｜VP CP IP │ 自分の資源と得点
│ 帯：いますべきこと                                │
│ ［解決中・次1 ▾］          ［取り消し］［ボタン］ │
├──────────────────────────┤
│                                                  │
│   盤面1枚（共通／街／キャラ／工業／みんな）       │
│   街は2本指で拡大・移動、＋−全体のボタン          │
│                                                  │
├──────────────────────────┤
│ ━ 手札 4                              開く ▴    │ 手元のシート
│ 共通サプライ（置けるときだけ地形・道）・捨札・山札・ディスク・ダイヤ │
│ （開くと）手札のカードを横に並べる                │
├──────────────────────────┤
│ 共通 │ 街 │ キャラ │ 工業 │ みんな              │ 盤面の切り替え（対象のある面に●）
└──────────────────────────┘
```

- 盤面は1枚ずつ表示する。共通＝メインボード（繁栄トラック・アクションエリア・フリーアクション・スキルタイル）と、ラウンド支援ボード・模倣ボード・マイルストーン・最終得点計算を縦に並べたもの。キャラ＝個人ボード（プレイしたカードを含む）。工業＝工業発展ボード。
- 手元のシートは常に下に出し、畳んだ状態でも共通サプライ・捨て札置き場・市民デッキ・手元のディスクとダイヤが見える。手札のカードはシートを開くと出る。
- みんな：プレイヤーの一覧。名前を押すと、その人の街・キャラボード・工業ボードを読み取り専用で表示する（上部に「〇〇さんの場を表示中［自分に戻る］」）。自分に選択が来たら自分の場に戻る。

- 帯は下の1行（文が長いときは折り返す）。

## 22.4 共通の改善（縦持ち・横持ち）

- **タップだけで操作する（2026-10-13 改訂、ユーザー指摘による）。** スマートフォンではドラッグをやめ、「タップで持ち上げる → 置き先をタップ」と「対象をタップ」だけで操作する。指を動かしたら持ち上げず、手札・盤面の枠・小窓のスクロールに任せる。理由：手札を横にスクロールしようとするとカードがドラッグされてしまい、カードをプレイできなかった。PC（横長）はドラッグとクリックの両方を従来どおり使える。持ち上げているあいだは、帯に「持ち上げ中：〇〇」と「置き先をタップしてください」を出し、「戻す」ボタンで下ろせる。
- **対象のある面を知らせる。** いま光っている対象（持ち上げ中なら置き先）がある面のタブに●印を付け、タブの地色を変える。対象がいまの面になければ、対象のある面へ自動で切り替える（§4.2 を引き継ぐ）。手元のシートは、手札が主役の選択（捨てる・残すなど、対象がすべて手元にあり、手札のカードを含む場面）と、持ち上げたものの置き先が手札の枠（候補を手札へ・持ち越し枠）のときに自動で開く。それ以外で手札のカードが対象のときは、シートの見出しに●印を付ける。
- **解決中／次の一覧を畳む。** 盤面を覆わないよう、帯の中の「解決中・次N ▾」の札に畳み、押すと帯の中に開く。先に解決する効果を選ぶ場面（`orderEffects`）だけは開いたまま出す。
- **地図の拡大縮小。** 2本指でつまんで拡大縮小し、1本指で移動する。タッチの端末では地図の右下に「＋」「−」「全体」のボタンを出す。
- **押せる大きさ。** 帯のボタン・タブ・サプライの山・展開ボタン・地図のボタンは 44×44px 以上にする（§14）。
- **盤面の縮小。** キャラボードと工業ボードは本来の幅が画面より広いとき、幅に合わせて縮めて表示する（CSS の zoom。縮めても操作はそのままできる）。共通の盤面は幅 360px 以上で組み、それより狭い画面では縮める。
- **アクションディスクの山。** 狭い列に収めるため、共通サプライのアクションディスクの山は、持ち上げられるときだけ出す。
- **画面の高さ。** アドレスバーの出入りで表示域が変わる端末に合わせ、画面の高さは `100dvh` を使う。ノッチのある端末では安全領域の内側に配置する。ホーム画面に追加して開くと、ブラウザの枠なしの全画面で動く。Android などで全画面にできるブラウザでは、メニューに「全画面」を出す。

## 22.5 誤操作の防止（タップのあとのクリック）

- タップで持ち上げると、スマートフォンでは表示中の面やシートがその場で切り替わることがある。ブラウザはタップのあとに同じ位置へクリックを遅れて届けるため、切り替わった先の要素（置き先のヘクスなど）に当たると、意図しない操作になる。
- そのため、持ち上げられる要素をタップしたあとの最初のクリックは捨てる（500ms 以内）。

## 22.6 受け入れ基準（§16 への追加）

- `e2e/autoplay.mjs` の `portrait`（390×844）と `landscape`（844×390）で、タッチ操作だけの自動プレイヤーが 2〜4人・ヴァリアントありなしの1局を打ち切れること。安全網に落ちた合法手・はみ出し・情報漏れ・ページのエラーが0件であること。
- PC（`mouse`、1280×720）の自動対戦が従来どおり通ること。
