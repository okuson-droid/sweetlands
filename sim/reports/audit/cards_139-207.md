# 市民カード監査（139〜207枚目：p10-r1c4 〜 p14-r3c5）

対象：`cards_side_by_side.md` の 1415 行目〜末尾（69枚）。文面（main_text・auto_text）と、アイコン（main_icons・auto_icons）をパーサー（`src/game/cards.ts`）が変換した構造（Eff）を1枚ずつ突き合わせた。構造は `citizen_cards.json` を `cards.ts` で再変換して側面比較表のものと同一であることを確かめた。

判定の前提として確認した読み方（`rules_excerpt.md` §6.9・§12.5・§13.2、`cards.ts`、`queries.ts`、`engine.ts`）：
- `=>` は `cond.each=false`（満たしていれば1回だけ）、`=>*` は `cond.each=true`（満たしている回数分。`floor(count/n)` 回、複数条件は最小値）。`->` は `pay.repeat=false`（1回支払い）、`->*` は `pay.repeat=true`。
- 連鎖 `コスト -> 条件 =>* 効果` は pay の then に cond を入れ子にする（コスト1回支払い後に回数分）。ユーザー確認済み（§12.5）。
- `hexM` などの塗りつぶし地形は `backOnly:false`（表裏問わず）、`hexM裏` は `backOnly:true`。
- `playedMin` などはオールマイティ産業のカードも1枚に数える（`playedCount`、§13.2）。`tShort` などのタグは自身のタグも数える（§6.9、`tagCounts` は `played` に積んだ後に解決）。
- `CP2` を条件側に置くと `score:cp` カウンタで `n=2`（都市点2点につき）。`[Wd]` を条件側に置くと `income` カウンタ（収入値2につき）。
- `placeBldW` は `building.onTerrain:'W'`（麦畑タイル上のみ。首都は対象外）。`placeBld` は裏返し済みタイルか首都。`bldOnM` は鉱山ヘクス上の建物駒の数。
- 収入値の支払い（`[G]` を矢印の左に置く）は `cost.income`。`canAfford` が収入値の不足を確認する。

判定の集計：一致 65／疑い 0／文面側の問題 4。

## 疑い・文面側の問題の一覧

疑い（構造が文面と違う読み）：該当なし。

### 文面側の問題（4件）

- p10-r3c4 イヴリン・ストリベリー：文面「鉱業の産業ボーナスを得る」、アイコン `ibMin`、構造 `ib row:'min'` は互いに一致している。
  しかし要確認「産業ボーナスが鉱業か任意か」が残っており（`rules_excerpt.md` §14 にも記載）、メモも「反射で上部の色が飛び気味なので ib? の可能性も残る」と読みを確定していない。
  任意なら `ib?` → `ib`（row 未指定、プレイヤーが列を選ぶ）に変わる。実物で上段帯が単色か3色かを確認したい。

- p12-r1c1 フランシス・フィグニュートン：文面「麦の収入値を2下げて麦畑タイルに建物駒を1個置く」と構造 `building.onTerrain:'W'` は一致している。
  しかしメモが「白台座の placeBld の可能性も少しある（Patrick の白台座と比べると色付き）」と読みを確定していない。
  汎用なら首都や他地形の裏返し済みタイルにも置けるため合法手の範囲が変わる。p03-r1c5・p14-r2c1 と合わせて台座の色を実物で確認したい。

- p14-r2c1 フィオナ・フリーズ：文面「麦4個を1回支払い、麦畑タイルに建物駒を1個置き、クッキーラビット駒を1個置く」と構造（pay wheat 4 → building onTerrain:'W' ＋ rabbit 1）は一致している。
  しかしメモが「台座が淡いオレンジ/ピーチ色（凡例の麦畑より淡い）。白台座の placeBld の可能性もあり」と読みを確定していない。
  p12-r1c1 と同じ論点で、麦畑限定か汎用かで置ける先が変わる。

- p14-r3c2 ヴィヴィアン・ヴェルヴェット：効果の構造（任意の基礎資源5を1回支払い、任意タイル1＋道1＋建物1（汎用）、オートは任意タイル1）は文面と一致する。枠内が点線で2行に分かれている点は、1行目が「5 R? ->」で終わり右側が空なので、2行で1つの効果と読むメモの判断が正しい。
  要確認はコスト（反射で読めず20と推定、§14）。コストはパーサーの対象外だが、プレイ可否と最終得点（ゴールド）に直接効くので実物で確認したい。

補足（判定には影響しない）：
- カタカナ名と英語名の不一致：p10-r1c4（ヘレナ／Henrietta、メモあり）、p14-r3c3（ユリア／Yolanda、メモなし）。いずれも印刷どおりのカタカナを採る方針なら問題ないが、p14-r3c3 はメモがないので印刷を確認しておきたい。
- 連鎖矢印のカード（p11-r2c2・p12-r3c1・p13-r2c1）は、いずれも pay→cond の入れ子で「コスト1回支払い後に条件の回数分」になっており、§12.5 のユーザー確認済みの解釈と一致する。
- 都市点を条件側に置くカード（p11-r1c4・p11-r2c5）は `score:cp` カウンタで解決しており、前半の p02-r1c3 と同じ扱い。
- ブラウニータグを持ちながらブラウニー割引のないカード（p12-r1c4 など、産業タグなしの8枚）はデータ全体で一貫しており、割引の有無はタグとは別の印刷と見る。
