# 市民カード効果エンジンの意味論監査

対象：`src/game/cards.ts`（アイコン表記 → `Eff[]`）、`src/game/types.ts`、`src/game/queries.ts`（数え上げ）、`src/game/engine.ts`（効果の解決）。
照合先：`sim/out/audit/rules_excerpt.md`（§6.9・§12.5・§13.2 を中心に）。
観点は「効果の種類」の実装であり、個別カードの表記の正否は別担当の範囲である。行番号はすべて 2026-10-20 時点の各ファイルのものである。

判定の記号：
- 一致：ルールの文面と実装が合う（根拠のコードを示す）。
- 不一致：ルールの文面と実装が食い違う。
- 未決：ルールの文面だけでは決められない（実装は一方の解釈を取っている）。

## (2) 不一致・疑いの詳細

ルールの文面に反すると確定できた箇所はなかった。実装が一方の解釈を取っていて、ルールの文面だけでは正否を決められない（持ち主に確認すべき）箇所が 7 件ある。

### 2.1 「->」の支払いが任意になっている（A6）

- コード：`engine.ts` 1210-1220
  ```ts
  ask(s, t, 'payConfirm', `${costLabel(e.cost)}を支払って「${describe(e.then)}」を得ますか`,
    [{ id: 'pay', label: '支払う' }, { id: 'skip', label: e.repeat ? 'もう支払わない' : '支払わない' }], 'confirm');
  ```
- ルール：§12.5「〜を1回支払い」。任意か強制かは書かれていない。カードの文面も「鉄3個を支払い、道駒を2つ置く」のように断定形。
- 違い：実装ではタグ目的でカードをプレイし支払いを拒むことができる。
- 影響：`->` を持つカード全般（例：フラニー・フランジパン `3 I -> 2 placeRoad`、マーゴット・マロン `1 D -> 2 placeBld`）。

### 2.2 払えないときに効果が無言で消える（A7・E1・E4）

- コード：`engine.ts` 1209 `if (!canAfford(s, p, e.cost)) return;`
- ルール：明文なし。
- 違い：ログにも画面にも「支払えなかった」旨が残らない。収入値コスト（`[G] ->`）で収入値が足りないときも同じ。
- 影響：収入値コストのカード 25 枚（例：マダム・マカロン `2 [G] -> 1 prosO`、レイラ・レイク `1 [I] -> 2 [Wd] 2 [W]`）。収入値を 0 未満にできるかは別途確認が要る。

### 2.3 連鎖矢印で条件回数 0 でも支払いを求める（A8）

- コード：`engine.ts` 1214 の確認文は `describe(e.then)` = 「条件に応じて…」で、回数を示さない。
- ルール：§12.5「コストを1回支払い、その後、条件を満たしている回数分」。文面どおりではあるが、0 回のときに払うかは書かれていない。
- 影響：ヴィオラ・ヴィヴィッド `2 W -> 2 tWagashi =>* 1 prosO`、ユージーン・ユズ `1 D -> 1 tWagashi =>* 1 placeRoad`、ジェラート・ジーニアス `3 W -> 1 tWagashi =>* 1 hexW`。

### 2.4 「地図ボード上の建物駒」に時計塔・研究所・ショップを含めている（B9）

- コード：`queries.ts` 180-182
  ```ts
  export function buildingCount(p: PlayerState, type?: BuildingType): number {
    return Object.values(p.hexes).filter((h) => h.building && (!type || h.building === type)).length;
  }
  ```
- ルール：§12.5「数え方はアイコンのとおり」、§9 では「建物駒個数（時計塔含む）」。カードの文面についての明文はない。
- 影響：モニカ・マロンマジック `1 bld =>* 1 G`、ウィリアム・ウェファー `3 bld =>* 3 Wd`、カレン・カルアカプ（パス時 `2 bld =>* VP1`）、オートメーション能力で `N bld =>` を持つ 6 枚。

### 2.5 カード由来の「建物駒を置く」が無料（F5）

- コード：`engine.ts` 884 `pieces = availablePieces(p).filter((pc) => !e.viaAction || canAfford(...))`、916 `if (e.viaAction) payFixed(...)`。カードの `placeBld` は `viaAction:false`（`cards.ts` 72-74）。
- ルール：§6.4 はアクションスペース経由の費用を述べる。カードの「地図ボード上に建物駒を1個置く」が費用を免除するかは抜粋に明文がない。工業トラック16マス目「建物駒1個置く」も同じ扱い。
- 影響：`placeBld` を持つカード（例：ザンダー・ゼスト、ニール・ナポレオン、ステファン・ストロベリースワール、ルイス・ライムの条件側）。

### 2.6 ブラウニー割引の率と上級スキル10（C3）

- コード：`engine.ts` 475 `if (c.brownie || hasSkill(p, 10, true)) cost -= tagCounts(p).ブラウニー;`
- ルール：抜粋に割引率の記述がない（タグ1個につき1ゴールドと仮定している）。上級スキル10の内容も抜粋外。
- 影響：`brownie_discount` 付きのカード全般。

### 2.7 連鎖の右側の順序は固定（C8）／列への追加位置（D5）

- コード：`engine.ts` 1255 `tasks(t.player, e.then, t.src)`（表記順）、1956 `p.automated[row].push(id)`（末尾）。
- ルール：§6.9「任意の順」が1本の矢印の右側にも及ぶか、オートメーション化したカードを列のどこに加えるかは明文なし。
- 影響：データ上はいずれも有利な順に並んでいるため実害は見当たらない。

### 参考：確認したが問題なしとした点

- `cond` の回数は実行時に数えるため、同じカードの先行効果（タイル配置等）を反映する。自身の効果で条件が増える `=>*`（例：`N hexW =>* 1 hexW`）はデータ上存在しないので、回数を先に確定して k 回積む方式（596-598）で差は出ない。
- 産業ボーナスの入れ子は深さ 1 までしか起きない（`runIb` は深さ 0 でのみ呼ばれる）。保留分は `ibEnd` で元の順のまま前詰めされる。
- パス時カードの効果は `main` に `clock` 接頭辞付きで入り、`parseLine` 137 で取り除かれる。`convert` 176 で `auto` は null。
- `payFixed` に渡す前に `anyBasic`・`hand` を 0 にしてから内訳を尋ねる（1231）。手札の支払いでは §6.0 を `canLoseCards` で守る（420）。

## (3) テストで確かめられていない項目

既存テストは `tests/cards.test.ts`（変換の網羅・連鎖の構造・収入値コストの構造）と `tests/rules.test.ts`（§2〜§10 の盤面処理）である。効果の種類の意味論で、実行時の振る舞いが直接検証されていないものを挙げる。

1. `pay`：支払う／支払わない、`->*` の繰り返しと「もう支払わない」、払えないときに飛ばすこと、収入値コストの減算と不足時の扱い、手札コストの選択と §6.0。
2. `cond`：`=>` が1回で止まること、`=>*` が `floor(count/n)` の最小値になること、複数項目の条件、実行時に数えること（先行効果の反映）。
3. 連鎖 `-> =>*`：支払い後に条件を数えること、条件 0 回の挙動。
4. 条件の数え方：`tagCounts` に自身・パス時カード・オートメーション化したカード・特性タグが入ること、`playedCount` でオールマイティを各列に数えること、`bld`・`bldOn`・`city`・`rabbit`・`auto`・`score`・`income` の各 `count`。`terrainCount` のみテストあり。
5. カードのプレイ：ブラウニー割引が自身を除くこと、支援タイル13の −3、割引後 0 で止まること、プレイ時にタグが即時に所持されること、`orderEffects` が単純効果だけのとき尋ねないこと。
6. オートメーション化：`afterPlay` の提示条件（産業タグなし・上限・ダイヤ不足で出ないこと）、支援タイル14で 0 になること、パス時カードに出ないこと、`drawAutomate`・カルメンの自由オートメーション化が即時能力を発動しないこと。
7. 産業ボーナス：印刷能力→カードの順、解決中に発生した産業ボーナスの保留と解除、「任意の産業ボーナス」の列選択、スキル12の3点。
8. パス時カード：`passRest` ⑥ で都市点・工業点の加算後に解決されること（`IP2 =>* VP1` が今回分を含むこと）。
9. 得る側：`ib` の n 個展開、`draw4` の倍率、`VP5` の `n * inner`、`placeBld` が無料であること、`placeBldW` が首都を除くこと、`hex?` だけが特殊地形ヘクスを選べること。
