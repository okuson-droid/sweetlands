## 2. 実験設定

### 2.1 条件

1人プレイ（`createGame({ players: 1 })`、ラウンド支援は2人用の5列、アクションエリアは2人用）。キャラクターはエリ・マカロン、地図ボードは条件で固定（A面は受け取られていない最初のボードの A面）、ラウンド支援駒の初期位置は AI が選ぶ。マイルストーンの獲得（`fa4:*`）は AI の選択肢から外す。得点は `finalScores` の内訳からマイルストーンと最終得点計算タイルの行を除いた合計。設定はアプリの `?auto=1&players=1&seed=N` と同じ（人の基準プレイと初期状態が一致することを `human` コマンドで確かめる）。

### 2.2 AI

- v0：合法手（`fa4:*` を除く）から一様に乱択。
- v1：手番の選択待ちで、合法手の候補ごとに、細かい選択を1手ずつ評価関数で選びながら手番の選択待ちに戻るまで（パスならクリーンナップまで）仮に進め、評価関数で比べる。両替のフリーアクション（fa2・fa3・fa5・fa6・fa7d・fa7h）のあとにだけ選べるようになる主行動は、両替を前に付けた候補として加える。評価の上位4候補には passGain の項（いまパスしたら得る得点 × 残りのパスの回数）を足して選ぶ。主行動のあとのフリーアクションは、手番を終える場合より評価が上がるときだけ選ぶ。主行動の前の両替は1手番に6回まで、逆向きの両替（fa3 と fa5 など）の行き来を禁止する。ラウンド支援駒の置き場所（初期と、パスのとき）は、次の手番まで進めて評価する。スキルタイルの選択は、手番に戻るまで進めて passGain の項まで含めて比べる。
- v2：§4 に記す。
- 決定化：先読みの局面では、市民デッキの残りを ID 順に並べ替えてから AI の乱数で混ぜ直し、エンジンの乱数の状態も AI の乱数で置き換える。
- 決め打ちのフリーアクション：時計塔駒を置けるなら置く（clock）、パスの前にディスクと手札（1枚を残す）を基礎資源に替える（prePass）。切り替え可能。

### 2.3 評価関数（26個の重み）

今ゲームが終わった場合の得点（上記の集計）に、重み × 特徴量の和を足す。終局した局面では得点だけ。特徴量（`sim/src/evaluate.ts`）は、ゴールド・麦・木材・鉄・ダイヤ・手札・ディスク、収入値（ゴールド・麦・木材・鉄）× 残りの収入フェイズ数、passGain、表向きの地形タイル、建物駒のない地形タイル、都市の数、建物駒、食料トラック、工業マーカー、繁栄トラックの歩数の合計、時計塔駒の条件の進み具合（キャラクターのデータから一般的に読む）、オートメーション化したカード × 残りの収入フェイズ数、手元のカード、スキルタイル、クッキーラビット駒、道駒、港までの近さ（港ごとに首都とつなぐのに要る地形タイルの残りの枚数を 0-1 BFS で求め、上限6で合計したものの負値）。キャラクター固有の知識は持たせていない。

### 2.4 重みの調整の規約（第5版）

`sim/scripts/tune_all.sh` に固定した。

- 方法：CEM。各反復の候補0は前の反復の平均。同じ反復の候補は同じシード・同じキャラクターで比べ（共通乱数）、シードは反復ごとに入れ替える。分散の下限 0.05。初期の幅は「初期値の絶対値と 0.2 の大きいほう × 係数」。

## 4. 本測定に入らなかった理由：v2 が v1 より弱く、時間の予算も超える

### 4.1 経過

1. 最初の v2（第5版の K 個の決定化つき）は、各局面の候補を「1手だけ進めた局面の評価」で上位に絞ってから解決まで進め、主行動の列をラウンドの終わりまで列挙していた。v1 の重みのまま同じシードで比べると、v1 の平均 66.0 に対して v2（中）は 49.3（8局）だった。地形タイルを置くなど、細かい選択を解決するまで価値が出ない行動を、1手だけの評価で最初に捨てていたためと考えた。この v2 で始めていた v2 の重みの調整（`interim/tune_logs/v2_common_A.txt`、2反復）は止め、結果は使っていない。
2. v2 を作り直した：最初の手は v1 と同じくすべての候補を解決まで進めて比べ、上位 R 個だけを深く読む。各候補について、混ぜ直した並び K=2 個のそれぞれでラウンドの終わりまでの列をビーム（幅 W、深さ D、1つの局面から解決まで進める候補 E）で列挙し、最良の葉の評価値の平均で選ぶ。葉（パスしたあと）の評価には、v1 の評価の passGain の項と物差しをそろえるため、そのパスで実際に得た得点 × 残りのパスの回数 × 重みを足した。

### 4.3 読み取れること・読み取れないこと

- 言えること：8局の範囲では、同じ重みのまま探索を増やすほど得点が下がる（大が最も低い）。v1 の重みで評価関数の誤りを、深い探索が拾っている形である。v2 の重みは調整し直す計画（第5版 §6.4）だが、調整しても「探索を増やすと弱くなる」性質が残るかは分からない。
- 言えないこと：8局の差（v1 と v2 中の差 5点）は、局ごとの標準偏差（約9点）に比べて小さく、統計的には確かでない。ただし方向は一貫している（v2 の3段階すべてで v1 未満）。
- 時間：v2 中は 27.5秒で、予算（20秒）を超える。スキル梯子（小・中・大）で20条件 × 100局を回すと、v2 だけで約15時間（4コア）かかり、パイロット全体の見積もりは約20時間になる。12時間を超えるため、規定により本測定に入らず止めた。

## 5. 解釈（現時点）

- v1 は港を4つともつなぎ（100局中100局）、地形タイルで繁栄トラックを進め、K エリア（6ゴールド）と I エリア（ダイヤ）を繰り返してゴールドを貯める打ち方に収束している（ゴールドの点が平均 27〜30点＝終局時に 135〜150ゴールド）。カードはほとんどプレイせず（1局に約1枚）、時計塔駒は一度も置いていない。エリ・マカロンは開始時のゴールドの収入が多く（18）、この打ち方はキャラクターの特性に合っているが、人がこれより高い得点を取れるかは、人の基準プレイで確かめる必要がある。時計塔能力（パス時に基礎資源の収入の最小値の勝利点）を一度も使っていないため、この打ち方のままでは時計塔能力の価値を測れない。
- 調整の雑音は約3点（追加調整の A と B の差 3.4点）で、追加調整の寄与（−1.3〜+3.5点）と同じ大きさである。P2・P3 の効果のうち3点程度のものは、重みの調整の違いだけで入れ替わりうる。
- 決め打ちのフリーアクションは、この打ち方では一度も発動しなかった（寄与0）。

## 5B. 評価関数の第2版（マスター指示による強化の試み、結果は不採用）

## 5C. 打ち方の型を候補にする方式（マスターの承認による強化の試み、結果は不採用）

§5B の「次の候補」2 を、マスターの承認を得て試した。手で書いた型を使う点は計画書 §4 の「戦略を人が書かない」からの逸脱であり、承認を得て変えたものである。

### 作ったもの

- `sim/src/templates.ts`：打ち方の型。型は、ラウンドの区間ごとに「評価関数の重みの倍率」「今終わった場合の得点の倍率」「得点のうちゴールドの分の倍率」を持つ。型の中の細かい手は v1 と同じ方法で選ぶ。型は8つ（base：倍率なし、engine2・engine3：第2・第3ラウンドまで収入・カード・オートメーション・時計塔を重く見る、spend4：第4ラウンドまでゴールドを貯めない、basic2・basic3：基礎資源の収入を重く見てゴールドを貯めない、rabbit、build）。
- `sim/src/ai.ts`：型を固定して打つ設定（`--template`）と、ラウンドの頭ごとに型の候補をそれぞれ対局の終わりまで模擬して選ぶ設定（`--templates`、`--templateK`）。あわせて、v1 の評価の上位の主行動（とパス）を、それぞれ対局の終わりまで v1 で模擬して最終得点で比べる v1r（1手だけ方策を改善するロールアウト）を作った。模擬では候補の間でデッキの並びと AI の乱数をそろえる（共通乱数）。

### 結果（エリ・マカロン × A面、重みは v1 追加 B）

| 型 engine2 / engine3 | シード1〜8 | 58.9 / 57.0 | カードのプレイが1局 0〜1枚から 2〜7枚に増えたが、得点は下がった |

### 読み取れること

- AI の弱さの中心は、収入（とくに基礎資源の収入）を育てる流れを打てないことである。収入は「地形タイルを置く → 道駒や建物駒で裏返す → 裏返しの効果で収入1歩か繁栄トラック1歩を選ぶ」で増える。人は麦の収入を 8 → 14 → 23 と増やし（第2〜第4ラウンドの頭）、その資源で毎ラウンド 10〜14回の主行動を打った。AI は基礎資源の収入が 2〜5 のまま、主行動は1ラウンド 4〜8回で、ゴールドを 100 以上貯めて終わる（ゴールドは5につき1点として「今終わった場合の得点」に入るため、評価ではゴールドが麦とほぼ同じ価値に見える）。
- 型で重みを曲げると、カードやオートメーションは増えるが、それを次の行動と得点に変える手順は出てこない。v1r は、模擬の中の打ち方（v1）自体がこの流れを打てないため、投資の手の先にも投資が実る局面が現れず、比べても差が出ない。型の選択も同じ理由で上限が低い。
- 以上から、強化には、模擬や探索の上に重ねる方式ではなく、打ち方そのもの（評価または方策）が「資源 → 地形タイル・道駒・建物駒 → 裏返して収入 → より多くの主行動」の循環を打てるようにすることが要る。候補は、評価関数の学習（§5B の候補 1。人の記録を教師にする）と、この循環を手順として打つ方策（ルールの知識を使うため、§4 からさらに外れる）である。

### 0-4. 損な変換の往復（型 L2）の原因

型 L2 の局面（シード3・34・54、第5ラウンド、手札0、ゴールド111〜149）で、各手の評価と特徴量の寄与を出した（`interim/stage0/loss_L2_seeds3-34-54.txt`）。

- **パスの評価**：パスすると対局が終わるため、評価は確定した得点（54・64・73点）だけになる。
- **両替（fa3）の評価**：パスしない局面では、得点の上に重み付きの特徴量が足される。
  - ゴールドの項だけで 38〜52点ある（ゴールド × 0.355）。
  - そのため、評価は 123〜155点と、パスより 60〜80点高い。
- **結果**：AI は、1手番の両替の回数の上限（6回、`MAX_CONVERSIONS`）に達するまで両替を続け、それからパスする。L2 の「fa3 ×5 → fa6 → パス」は、この上限そのものである。
- **原因**：重みの不整合でも同点処理でもなく、パスと続行の評価の基準のずれである。
  - パスした局面だけが確定した得点になり、ほかの局面は「まだ使える資源」の価値を持ったままになる。
  - 最終ラウンドでは、この差が最も大きい。
- **直し方**：段階1 の評価関数で、最終ラウンドの資源の価値を「残りの手番で実際に変えられる分」に限ることで解消する見込みである。
  - 段階0 では直していない。両替の上限で止まっているため、影響は1局あたり 20ゴールド前後（4点前後）と見込む。

| 0-3：効果の捨てが0枚 | 不具合による捨ては0。評価で見送った11枚と得るものがない5枚は残る |
| 0-2：表が出ている | 出た（上の表） |
| 参考：シード1〜100 の平均 | 67.3 → 72.5（+5.2） |

段階1 の重点への示唆：0-2 から、育てる側と変換する側の両方が弱い。0-4 から、パス（とくに最終ラウンド）と続行の評価の基準をそろえることが、見込みの式の要件になる。

## 6. 改善提案と判断が要る点

判断をお願いしたいのは、本測定の進め方である。選択肢と見込みは次のとおり。

1. v1 だけで P1〜P3 を先に回す（推奨）：v1 追加 A・追加 B・共通 A の3構成 × 20条件 × 100局で約2時間。頑健さの関門のうち、重みの調整の雑音の組（v1 A × v1 B）だけを判定できる。探索の方式・量の組は v2 の改善後に回す。人の基準プレイがそろえば、強さの関門を v1 で判定できる（第5版では判定の構成は v2 中だが、v2 が v1 より弱いあいだは v1 で判定するのが妥当と考える）。
2. AI の改善を先に行う：v2 の探索を増やすと弱くなる原因（評価関数の誤り）を、v1 の打ち方の偏り（カードをプレイしない・時計塔を使わない）と合わせて調べる。候補は、カードの価値の特徴量（手札・手元のカードの効果の見込み）、時計塔能力の見込み（passGain の項がパス時の時計塔能力を拾うのは、時計塔駒を置いたあとだけである）、v2 の重みの調整（v2 用の重みで、探索を増やしても得点が下がらないかを確かめる）。所要時間は読めない。
3. v2 の局数を減らして予算に収める：スキル梯子の小・中だけ、または50局ずつにする。ただし v2 が v1 より弱いままでは、頑健さの関門の判定に使う意味が薄い。

人の基準プレイの1局目（§5A）により、現在の AI は強さの関門に不合格になる見込みが極めて高い。そのため推奨を改める：本測定（1 と 3）より先に 2（AI の強化）を行う。強化の候補は、事例分析から次のとおり。

- 評価関数の形を変える：繁栄トラックの「レート × 数」を、トラックの位置と対象の数の両方から見込みで出す項（例：残りのラウンドで増やせる数の見込み × 現在のレート、トラックを1歩進めたときのレートの上がり方 × 現在の数）。収入の項は「残りの収入フェイズ数」に比例させるだけでなく、序盤ほど得点に変わる機会が多いことを反映する。
- カードの価値：手札・プレイしたカードの効果を、収入の増加・オートメーションの見込みとして評価する項。
- 地平：1手番（v1）やラウンドの終わり（v2）までの先読みでは、第1〜第2ラウンドの投資が第4〜第5ラウンドに実る構造を読めない。評価関数の学習（計画書 §9：「次の手番開始の局面 → 最終得点」を対局の記録から学習する）を前倒しする価値がある。人の記録はその教師データにもなる。

## 7. 全キャラクターに広げたときの所要時間の見積もり（v1 のみ）

v1 は1局あたり約4秒（1コアあたり）。280条件（14キャラクター × 20条件）× 100局 × 1構成で 11.2万秒 ≈ 31時間（1コア）、4コアで約7.8時間。頑健さの関門の v1 の2構成と共通の重み版を合わせた3構成では約23時間（4コア）。v2 を加える場合は、v2 の改善後に測り直す。

## 8. 再現のためのコマンド

`sim/` で実行する。

```
node build.mjs main report cases            # dist/ にまとめる
npx tsc --noEmit -p tsconfig.json           # sim の型検査
scripts/tune_all.sh                         # 重みの調整と最終選考（v1 の4本。v2 の2本は §4 のため未実施）

node dist/main.cjs check --ai v1 --weights reports/pilot/weights/v1_eri_A.json --games 30 --out out/p0/checks_v1.json
node dist/main.cjs human --records <記録.json,...> --out reports/pilot/human.csv
node dist/cases.cjs --records <記録.json,...> --weights reports/pilot/weights/<重み>.json --out reports/pilot/cases.md
```

本測定の手順は `scripts/measure_all.sh`、報告書の数値の生成は `node dist/report.cjs out/measure reports/pilot`。
