## 3. 決めたこと（Claude Code の判断。理由つき）

- 両替の一括とまとめ払いの選択肢は、AI の合法手から外した（`core.ts` の `legal`）。
  - 理由：選択肢の数が爆発して、1局が終わらない。
  - エンジンの仕様では、まとめた手は1単位ずつの手を繰り返したのと同じ結果になる。そのため、AI の打てる結果は変わらない。
- 連鎖の評価は、上位の候補（topK）の解決し直しと実際の細かい選択だけに使い、候補の順位付けと passGain には使わない。
  - 理由：全部に使うと1局が10分を超える。
  - 副作用として、順位付けの段階では D（道駒）などの価値が低く見えたままである。エリア D の使用は0回のまま変わっていない。
- `chainSub` を設定にした（既定は有効、`run --chain 0` で修正前と同じ動き）。修正前の結果を再現するためである。

## 5. 注意事項・落とし穴

- main のエンジンでは、両替とまとめ払いの選択肢が多い。sim 以外の道具（`llmplay.ts` など）で `getOptions` を直接使うと、同じ爆発が起きる。AI の判断には `core.ts` の `legal` を通すこと。
- 選択待ちの選択肢は、選択待ちを立てた時点で作られる。局面（資源・手札）を書き換えても `getOptions` の結果は変わらない。検査用の局面を作るときは、書き換えてから最後の1手を指して、選択肢を作り直させる（`cardcheck.ts` の `replayBefore`）。
- 連鎖の中の選択（深さ1）は、1手の評価と同点処理の乱数で決まる。そのため、同じ局面でも測るたびに評価が数点動くことがある（ユリア・ヨーグルトヤーンの例）。
- `ps aux | grep` で探したプロセスを止めるときは、同じコマンド行に探す文字列を含めないこと（自分のシェルを止める）。
