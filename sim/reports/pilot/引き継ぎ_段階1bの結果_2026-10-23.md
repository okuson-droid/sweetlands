## 2. 段階1b の結論（詳細は §5F）

- **(a)** 人のシード1の第5ラウンドの頭から、AI 乱数 1〜5 の平均。
  - W＝4・E＝6 は 327.2点、W＝8・E＝8 は 348.0点（最大357点）。
  - 同じコンテナの v1 は 322.4点、人は 444点。
  - 探索の効き目はあるが、人との差の多くは埋まらない。
- **(b)** v1 の100局を第5ラウンドの頭から打ち直すと、v1 との対の差は +0.4点（W＝4・E＝6・W＝8・E＝8 とも）。v1 の局面には、取り戻せる余地が小さい。
- **(c)** 人の第5ラウンドの手のうち、準備の手は E＝6 の候補から落ちる。
  - 落ちる手：J（20/32位）、H、fa5・fa6、s7 のフリップ、一部のカードのプレイ。
  - 得点の手（Q・A・O・M・P）は2〜6位に入る。
  - 人の手の列は、最初の手（J）で落ちる。
- **再計測（keepEven）**：パスしたら得る得点が親より下がらない手を候補に残す変更をした。それでも (a) は5局すべてが同じ値だった。次の深さで W 個のノードを選ぶときに、同じ順位の付け方で落ちるためである。
- **原因**：落ちる原因は、追補が直す対象に挙げた3つ（合法手の絞り込み、`chooseSub` の解決、同点処理）ではなかった。ノードの順位を「その場の得点」で付けることそのものが原因である。
- **時間**（1局面ずつ、同じコンテナ）：v1 は 6.7秒、W＝4・E＝6 は約9倍、W＝8・E＝8 は約15倍。

## 3. 決めたこと（Claude Code の判断）

- **計画の使い方**：計画は決定化した局面で立てる。実際の局面が計画どおりのあいだは続きを打ち、ずれたら立て直す。理由は、手番ごとに立て直すと1局面に10分を超えたためである。
- **ノードの順位**：パスの手を指して解決した局面の得点（`scoreTotal` ＋ `passGain`）で付ける。追補 §4 の補足2 のとおり、パス時の列の効果を含む。
- **keepEven**：設定にして残した。既定は無効。

## 4. 次の判断の材料

- **ラウンドの中の探索は効く。** 人の局面から +26点（348 対 322）。
- **それでも人に届かない理由は、準備の手から始まる鎖をたどれないこと。** 鎖の最初の手（J でカードを引く、資源を替える、ディスクを取る）に値を付ける手段が要る。候補は2つで、どちらも追補の前提に触れる。
  1. **先読みのロールアウト**：子の局面ごとに、残りのラウンドを v1 か貪欲な方策で打ち切って、その得点で順位を付ける。評価関数は使わないが、計算量が今の数十倍になる見込みである。
  2. **評価関数を葉以外にも使う**：準備の手の価値を評価関数で付ける。追補の「段階1b は評価関数を使わない」から外れる。
- **第3版の楽観は計画器でも埋まらない。** v1 の100局の第5ラウンドの頭で、第3版の評価値は平均 85.9点、計画器の到達点は 72.9点（差 +13.0）。
- **(b) の計測の限界**：(b) は v1 の局面から始めるため、計画の価値を測る力が弱い。人の局面は (a) の1局（シード1）だけである。人の基準プレイ（シード2〜5）がそろえば、(a) の局面を増やせる。

## 6. 注意事項・落とし穴

- 計画器（`planR5`）は1局面あたりのノード数が 1700〜3500 で、数十秒〜数分かかる。100局を回すときは、stage0 の `r5` をシードの範囲で分けて、並列に回すこと（3本で W＝8・E＝8 が約1時間）。
